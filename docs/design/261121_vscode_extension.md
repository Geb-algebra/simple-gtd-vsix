# Simple GTD の VS Code 拡張

- Status: Proposed
- Date: 2026-11-21

## 目的

**既存の SPA を VS Code のサイドバーに載せ、ワークスペースの Markdown と接続する。**
最初の反復では、パネルの切替、3 ファイルの読み込み、Inbox への追記を通して接続を検証する。

## 現在の決定

### 仕様

#### Markdown の保存形式

**保存先は対象ワークスペースフォルダー直下の `_tasks/` とする。**
`inbox.md` に未分類項目、`tasks.md` に Next Actions・Someday・Waiting for・Do at、`log.md` に日別の完了項目を置く。
各項目は通常の箇条書きとし、Do at の指定日は行末の `@YYYY-MM-DD` で表す。
ログの日付節は `## YYMMDD` で表す。

### 設計

#### サイドバー UI

**VS Code のサイドバーでは既存の `spa/` を使う。**
Inbox・TODOs・TADAs は実装済みの[縦並びパネル](261121_sidebar_panels.md)で切り替える。

## 重要な代替案

### Markdown のチェックリスト

- 対応する決定: [Markdown の保存形式](#markdown-の保存形式)
- Alternative: Markdown のチェックボックスで未完了と完了を記録する。
- 棄却根拠: 保存形式は通常の箇条書きに統一することが決まった。完了済み項目はログへの所属で表す。

## 未決事項

### 最初の試作と残る検証

**試作では、同じ画面コンポーネントを Webview 用の Vite エントリーから読み込む。**
画面遷移には React Router のメモリルーターを使い、表示中のパスは Webview の状態に保持する。
メッセージ経由で拡張ホストが Markdown を読み込み、Inbox への追加を書き込む。
保存済みファイルの作成・変更・削除を監視して画面を再読み込みする。
拡張のビルド、型チェック、lint、テスト 8 件は通過した。
VS Code 上での表示と操作感を確認したうえで、この接続方式を採用するか決める。

**この反復で保存に接続する操作は Inbox への追加である。**
分類移動・編集・完了・後回し・Undo/Redo・Project の保存と実行、複数ファイルの同時更新、VSIX の導入確認は今後の反復で扱う。

### 実装計画

#### 1. サイドバーと SPA の接続

**拡張ホストがサイドバーとファイル操作を担当し、Webview に載せた SPA が入力と表示を担当する。**
拡張本体とマニフェストは `extension/` に置き、Activity Bar の Simple GTD ビューコンテナーに `WebviewViewProvider` を登録する。
[VS Code Webview API](https://code.visualstudio.com/api/extension-guides/webview)

**パネル配置は、サイドバー向けに更新済みの `spa/` の実装をそのまま使う。**
Inbox・TODOs・TADAs を上から順に並べ、選択中のパネルが残りの高さを使う。
閉じたパネルはヘッダー全体を表示し、選択すると開く。
開いたパネルの内容はパネル内でスクロールできる。
カードは使える幅に収まり、Inbox の Project は先頭カードの左下、Next Actions の後回しは先頭カードの左上に置く。

**ブラウザ版と拡張版は React Router の読み込み・操作経路を共有する。**
`workspace.tsx` の `clientLoader` と `clientAction` が呼ぶ保存処理に、localForage と Webview メッセージの二つの実装を用意する。
Webview では `acquireVsCodeApi()` を一度取得し、要求 ID つきで読み込みと操作を送る。
ホストは Zod で要求を検証し、現在の状態とその版、または操作結果とエラーを返す。
ファイル変更の通知を受けた SPA は React Router の再検証で状態を取り直す。

**Webview 用ビルドは VSIX に同梱した資産だけで起動する。**
最初に、生成 HTML、React Router のルートと遅延ロード、CSS とフォントが Webview 内で読み込めることを確認する。
HTML から参照する資産を `asWebviewUri` で解決し、`localResourceRoots` を同梱資産のディレクトリに絞る。
CSP は読み込み元を絞り、インラインの起動スクリプトが必要な場合は nonce を付ける。
最初の試作では Webview 用の Vite エントリーで React Router のメモリルーターを使い、現在の画面を `getState` / `setState` で復元する。
折りたたまれたヘッダーと TODOs の All・Next Actions のリンクは、Webview 内のルーターで切り替える。
ブラウザでは既存の `/`、`/tasks`、`/next`、`/log` を使う。
[VS Code Webview API](https://code.visualstudio.com/api/extension-guides/webview)

#### 2. Markdown の保存と同期

**既存の `tasks/` との衝突を避けるため、選択したワークスペースフォルダー直下の `_tasks/` を保存先にする。**
単一フォルダーではそのフォルダーを使い、複数フォルダーでは対象を選択できるようにする。
フォルダー未選択時は開くか選ぶ操作を案内する。
対象確定後、必要なディレクトリと不足ファイルだけを作る。

| ファイル | 読み書きする内容 |
| --- | --- |
| `_tasks/inbox.md` | 未分類項目をファイル順に読み、追加は末尾に書く。 |
| `_tasks/tasks.md` | `Next Actions`、`Someday`、`Waiting for`、`Do at` の見出しと各項目を扱う。対象者は末尾の `@名前`、指定日は末尾の `@YYYY-MM-DD` から読む。 |
| `_tasks/log.md` | 完了項目をローカル暦日の `## YYMMDD` に追加する。新しい日付の見出しはログ本文の先頭の日付節より前に挿入する。 |

**3 ファイルのタスク項目は、通常の Markdown の箇条書きで読み書きする。**
新規項目は `- タスク名` の形式で書く。
UI で完了すると、元の項目を取り除き、完了日のログに箇条書きで追記する。
Markdown の更新範囲は対象行・見出しに絞り、説明文、コメント、未知の節、改行形式を保つ。

**指定日は `YYYY-MM-DD` の暦日として扱う。**
Next Actions には、指定日が今日のローカル暦日と一致する Do at を含める。
完了日と今日の判定には Webview 側のローカル暦日を使い、日付またぎで表示を更新する。
後回しは当日の Next Actions 表示順に適用する初版案とし、Markdown 上の分類順はドラッグ操作で変更する。

**Markdown の更新はフォルダー単位で直列化し、読み込んだ版に対して適用する。**
ホストは要求の版と編集対象のファイル内容を再確認し、外部変更や未保存のエディター編集があれば保存前に競合を返す。
タスク ID はホストが読み込んだ版の行に対応づけ、同名項目も区別する。
分類移動と完了は複数ファイルの変更を一操作として扱い、保存完了後に UI に結果を返す。
途中で失敗した場合は今回書いた内容がそのままのファイルだけを復元し、復元できなければ該当ファイルを示して実際の状態を再読込する。
保存・外部変更・削除はファイル監視とエディターのイベントで検知し、ビュー再表示時にも読み直す。
[VS Code API](https://code.visualstudio.com/api/references/vscode-api)

**Inbox の Undo・Redo は、適用済みの Markdown 編集を戻す操作にする。**
Ctrl/Cmd+Z と Ctrl/Cmd+Shift+Z を既存の Inbox 操作からホストに届け、対応する変更前後を復元する。
履歴はフォルダー単位でホストのセッション内に保持し、外部編集や分類済みカードの変更で無効化する。
後回し順もホストのセッション内で扱い、日付変更時に解除する。

#### 3. GTD 操作と Project コマンド

**既存 SPA の操作をホストで実行し、保存成功時にカードの移動を確定する。**
Inbox の Enter は Next Actions、右は担当者入力後に Waiting for、左は日付入力後に Do at、左の空欄確定は Someday、下は完了に対応する。
TODOs はタスク名・属性の編集、ドラッグによる並べ替え・分類移動、完了を扱う。
担当者・日付が必要な分類に移す場合は入力確定時に保存し、キャンセル時は元の位置に戻す。
Next Actions 表示では今日の Do at、次いで Next Actions を並べ、先頭カードの完了と後回しを受け付ける。
TADAs はログから日別件数を集計し、ヒートマップの日付を選ぶとその日の完了一覧を表示する。

**パネルをまたぐ変更には、SPA のカード移動と到着時の演出を使う。**
保存成功時にホストから返す移動情報で、カードを移動先パネルの内側へ動かす。
移動先が閉じている場合はヘッダーの内側に入り、到着時に受け入れ側のパネルが小さく動く。
動きを減らす設定では、移動と到着時の動きを省く。

**VS Code 版の Project ボタンと上矢印は、同じ設定コマンドを実行する。**
`simpleGtd.projectCommand` をユーザー設定として設け、ホストが設定からコマンド ID を解決する。
引数はタスク名と対象フォルダー URI を持つオブジェクト一つとする案を採る。
初版案ではコマンドが成功したときに Inbox から該当項目を取り除く。
未設定・失敗時は項目を残し、原因を UI に表示する。
成功後に Markdown の保存が競合した場合は、コマンド実行済みであることを表示し、コマンドの自動再実行を避ける。
Project の外部処理はコマンド側が所有し、この操作は Inbox の Undo・Redo の対象外とする。
VS Code 版の分類は IDEA の四つを使い、ブラウザ試用版の Project 分類はブラウザの保存処理で扱う。
[VS Code API](https://code.visualstudio.com/api/references/vscode-api)

#### 4. 実装順と完了条件

**Webview の起動を先に確かめ、データの往復から画面操作へ段階的に接続する。**

| 順序 | 実装 | 完了条件 |
| --- | --- | --- |
| 1 | 拡張マニフェスト、サイドバー、SPA の同梱と起動 | Extension Development Host で Inbox・TODOs・TADAs のヘッダーが縦に並び、マウスとキーボードで切り替えられる。狭い幅でもカードが収まり、低い表示領域では開いたパネル内をスクロールできる。ビュー再表示で画面を復元でき、スクリプト・CSS・フォントが読み込まれる。 |
| 2 | フォルダー選択、Markdown の初期化・解析・編集、メッセージ接続 | 既存の箇条書きを読み込み、Inbox への追加とログへの追記が通常の箇条書きで保存される。直接編集が画面に反映される。同名項目、コメント保持、競合、途中失敗を検証する。 |
| 3 | Inbox の振り分け、Undo・Redo、Project | キーとボタンで振り分けられ、複数ファイルにまたがる完了を取り消し・再適用できる。Project の未設定・成功・失敗・実行後の保存競合を検証する。 |
| 4 | TODOs・Next Actions・TADAs | 編集、ドラッグ、入力キャンセル、完了、後回し、ヒートマップ選択が動く。サイドバー内で日付入力のカレンダーとアイコンボタンのツールチップが表示できる。振り分け・完了時の閉じたパネルへのカード移動と、動きを減らす設定での表示を確認する。Do at の日付を Markdown から読み込んで編集でき、日付またぎで今日の対象が切り替わることを確認する。 |
| 5 | 配布用ビルドと VSIX | SPA の既存テストと型チェック、拡張ホストの結合テストを通す。生成 VSIX を別の VS Code プロファイルに入れ、開発サーバーなしで保存からログ表示まで確認する。 |

**初版はデスクトップ版 VS Code のローカルワークスペースを検証対象とする。**
Project コマンドの引数と成功条件、後回しと履歴の保持期間は、この計画で置いた初版案である。
`engines.vscode` の最低バージョンは、使用する API と実機検証の結果をもとに決める。
