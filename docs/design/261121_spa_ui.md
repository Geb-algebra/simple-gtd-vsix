# Simple GTD のブラウザ版 UI

- Status: Accepted
- Date: 2026-11-21

## 目的

[Simple GTD の UI 設計](ui/simple-gtd.md)に沿って、Inbox の振り分けからタスクの実行とログの確認までをブラウザで試す。

## 現在の決定

### 仕様

#### Inbox・TODOs・TADAs

共通ヘッダーを外し、各画面を同じ背景色、枠線、タイトル左のアイコンを持つパネルにする。Inbox と TODOs は上段、TADAs は下段に位置づける。Inbox を開くと右端に TODOs の左枠とアイコン、下端に TADAs の上枠と見出しが見える。TODOs を開くと左端に Inbox、下端に TADAs が同様に見える。TADAs を開くと上端に Inbox と TODOs の端が左右に並ぶ。開いていないパネルは、そのパネルがある方向に画面外まで続く形で見切れる。見えている端を選ぶと、そのパネルが画面の主領域に開く。

Inbox 上部に点線の枠で囲んだ＋ボタンを置く。通常時のボタンの背景は Inbox パネルと同色にし、ボタンの下中央に挿入先を示す下向きのシェブロンを置く。押すとその位置にタスクカードと同じ見た目の入力カードが現れ、タスク名の位置の入力欄にフォーカスする。名前を入力して Enter を押すか、フォーカスを外すと Inbox の末尾に追加する。空欄のままフォーカスを外した場合は、追加せず＋ボタンに戻る。入力欄の背景は通常時は白で、フォーカス中に色が変わる。空白以外の文字を入力するとカードの右端に「Press Enter to add」を表示する。空白だけの名前は登録できない。保存後は入力欄の位置に名前とチェックボックスのあるカードが現れ、Inbox の山へ移動する。追加は Undo・Redo の対象とする。Inbox では操作成功のメッセージを表示しない。

Inbox と Next Action はスタックの先頭だけを表示し、カードをパネルの左右中央に置く。Inbox では先頭カードの左隣に、カードと同じ高さの ghost スタイルの「Project」ボタンを置く。押すと先頭のカードが右の TODOs へ飛び、All の Project に入る。相手と日付のアイコンボタンは先頭カード内の右端に置く。Inbox の Undo・Redo はキーで操作する。画面にはキー操作の案内を置かない。振り分けや完了の Undo では移動先からカードが戻り、Redo では同じ方向へ送り直す。タスク追加の Undo と Redo でも、追加欄と Inbox の山の間の動きを逆再生・再生する。

Inbox、タスク一覧、Next Action で名前を直接編集できる。相手や指定日を持つカードは、その属性をクリックしてカード内で編集する。編集内容は Enter またはフォーカスを外したときに保存する。

Inbox から Waiting for または Do at に振り分けると、先頭カードの属性欄に入力欄が現れてフォーカスされる。日付欄ではその場でカレンダーを開く。相手名または日付を入力して Enter を押すと、カードが右の TODOs へ移動する。日付欄が空のまま Enter を押すと Someday に入る。入力せずにフォーカスを外すと、同じタスクが Inbox の先頭に残る。

Inbox と TODOs でチェックボックスを操作すると、チェック済みの表示を出してからカードが下の TADAs へ移動する。完了カードが TADAs に入ると、見えている TADAs パネルの範囲全体から祝福のエフェクトを出す。Inbox または Next Action の最後のカードを処理して表示が空になったときは、そのカードが占めていた範囲全体から祝福のエフェクトを出す。紙吹雪は発生範囲全体に現れ、それぞれが弾ける方向と逆にゆっくり動いてから、一斉に滑らかに折り返して加速し、拡散する。画面の動きを減らす設定では、移動と祝福のアニメーションを省く。

分類別一覧は Next Actions、Waiting for、Do at、Project、Someday の順で表示する。順序や分類はハンドルから変更できる。Next Actions と Someday のカードにも相手と日付のアイコンボタンを表示し、属性を入力して Waiting for または Do at に移せる。Next Actions のカードでは、空の日付欄で Enter を押すと Someday に移せる。移動先で相手や指定日が必要な場合は、先に移動先へカードを表示し、そのカードの入力欄にフォーカスする。有効な相手名や指定日が入っていれば、Enter またはフォーカスを外したときに移動を確定する。有効な入力なしでフォーカスを外すと元の分類と位置に戻す。

タスクカードは左からハンドル、チェック、タイトルの順に並び、相手と指定日はタイトルと同じ行の右端に寄せる。分類名はタスク一覧の見出しに表示する。ハンドルの左には余白を設けず、チェックボックスは 20 px 四方とする。タイトルは通常のテキストとして見せ、ホバー時に編集できることを示し、フォーカスするとその場で編集できる。カードにはパネルより薄い枠線と Tailwind CSS の `shadow-md` を使う。

Inbox、タスク一覧、Next Action、ログのカードで同じ幅・配置・余白を使う。カードの最大幅は 32 rem とし、狭い画面ではパネル内に収まる幅まで縮める。移動できないカードではハンドルの列を空け、属性がないカードでも属性欄の幅を確保する。チェックボックスは常に表示する。Inbox でチェックすると下矢印キーと同じ完了処理が走り、ログではチェック済みの状態を表示する。

TODOs の見出しの横に All と Next Actions のナビゲーションを置き、現在の表示を強調する。TODOs を開くと Next Actions を表示し、All を選ぶと分類別のタスク一覧に切り替わる。Next Action は今日の Do at を Next Actions より先に表示する。先頭カードの左にRedo2 アイコンの後回しボタンを置く。押すと先頭カードが上から山の裏へ回り、次のカードが現れる。TADAs のヒートマップを囲むカードは TODOs のタスク一覧と同じ幅に揃える。マスを並べる範囲の幅は最大 12.5 rem とする。日曜始まりの週を列に並べ、各日付を正方形で表示する。左端は Sun・Tue・Thu・Sat の行に曜日名を、上部は月初を含む列に月名を表示する。日付を選ぶと、その日の件数とカードを表示する。

### 設計

#### React Router SPA Mode

React Router Framework Mode の SPA Mode で新規実装する。Inbox、TODOs、TADAs と Next Action の表示状態はブラウザの URL で切り替えられる。SPA はリポジトリ内の `spa/` に置き、Vite と Bun で開発・ビルドする。

#### タスクの読み書きと UI

ブラウザのタスクデータは localForage に保存する。読み書きは React Router の `clientLoader` と `clientAction` を通し、保存済みデータとフォーム入力を Zod で検証する。カードは Inbox、タスク一覧、Next Action、ログで共用し、入力には Base UI ベースの shadcn/ui を使う。日付欄のカレンダーには shadcn/ui の Calendar と Popover を使う。 フォントは英字に Ubuntu、日本語に Noto Sans JP を使い、ビルドに同梱する。

## 重要な代替案

なし。

## 未決事項

ブラウザでの試用では、初回にサンプルタスクを用意し、変更を同じブラウザに保存する。Markdown ファイルへの反映と VS Code のプロジェクト用コマンドは、ホスト連携の設計が必要である。

日付判定にはブラウザの現地日付を使う。ヒートマップは直近 63 日を表示し、後回し順は当日中のみ保持する。Inbox の操作履歴は最大 50 件保持し、分類済みのタスクを編集・移動・完了すると履歴をリセットする。これらは試作用の設定で、実際の利用感を確認して決める。

試用中は `/`、`/tasks`、`/next`、`/log` を各画面の URL とする。タスク一覧のハンドルにはドラッグに加えて Alt と矢印キーによる移動を用意する。
